# NEAR review decisions

Recording time: 2026-10-28T16:44:18-04:00 (America/New_York). This record covers the local upstream 0.53.0 merge and its wallet-layer repairs. The user approved fixing NEAR before publication. The original independent reports remain available beside this file; their original line numbers describe the reviewed source before repairs.

## Decisions

- **SEC-1, ADV-1, NC-2: fixed.** Unknown NEP-141 transfers retain their emitting contract in `TransactionValue.TokenValue` or `RawValue`. `NearTransactionConverter` classifies unsigned unknown-token history as spam before any saved-contact exemption. The existing transaction-details fields expose the contract. `NearHistorySafetyTest` supplies a counterfeit USDC log naming a trusted contact and checks both identity and suspicious classification. Other chains' contact behavior and layouts are unchanged.
- **SEC-2: fixed.** `NearTransactionHistory.outgoingContext` filters successful, account-signed native transfers and known-token transfers before applying the recipient limit. Incoming rows and unsigned or unknown-token logs cannot replace genuine outgoing history. Work is bounded to 20 pages of 100 rows, with a repeating-cursor stop. Tests cover an incoming flood, forged outgoing logs, failed transfers and both scan stops. History older than that bounded window is not guaranteed to contribute to poisoning checks.
- **SEC-3, resilience NET-4: fixed by a local mitigation.** The pinned SDK is unchanged. `NearKitWrapper.verifiedTokenBalance` reads `ft_balance_of` from configured RPC sources, validates a JSON-string U128 amount and honors fail-closed Tor configuration. `NearTokenAdapter` publishes only independently verified token balances, preserves the previous verified display value with an error on failure, exposes no maximum while unsynced and rechecks the balance before estimate and send. Foreground verification repeats every 30 seconds; background polling stops. `NearTokenBalanceTest` covers exact values and malformed/overflow responses. Live RPC failure/recovery and observed traffic remain untested.
- **NC-1: fixed.** `BackupLocalModule` validates NEAR watch addresses and explicit named-account restore settings before persistence. Single-wallet restore rejects malformed identifiers; full-backup processing skips that invalid account without discarding valid siblings. The shared module uses the pinned SDK grammar because it cannot depend on the chain module. `BackupRestoreSettingsTest` covers valid, malformed and null settings; `NearAddressAndTokenTest` checks grammar parity against the pinned SDK. Encrypted full-backup UI round trips remain untested.
- **NC-3: fixed.** Missing or invalid token metadata yields a contract-tagged `RawValue`, never a zero-decimal token. Existing localized raw-unit formatting is used in history and details only for those tagged values. Tests distinguish a failed metadata read from a genuine zero-decimal token and preserve contract identity through absolute-value formatting.
- **NC-4: fixed.** The address filter includes successful internal native movements involving the watched account. `NearHistorySafetyTest` excludes failed movements and unrelated counterparties.
- **NC-5: fixed.** `NearKitManager` emits the wrapper and owning account as one binding after initialization, rather than relying on a conflated started boolean. `NearAccountManager` cancels the previous subscription, captures that binding, verifies it under the manager lock and enables only the owner's missing token wallets while that account is active. `NearAccountManagerTest` covers stale-owner suppression and account-specific enabled-wallet lookup. On-device rapid switching remains untested.
- **ADV-2: fixed.** `boundedNearAccountLookup` validates and deduplicates the indexer's account IDs before ownership checks, limits named candidates to 20, loads details sequentially and applies a 20-second overall timeout. Custom clients have no HTTP logging or redirects and require the Tor proxy when enabled. The existing failure/manual-entry flow remains available. `NearAccountDiscoveryTest` covers invalid/duplicate input, the cap, ownership, timeout and cancellation. A user with more than 20 discovered named accounts may need manual entry.

There are no pending source-confirmed findings from these four role reports. A fixed disposition describes the code repair, not a claim that every runtime vector has passed. Automated build/test results and explicit unrun vectors are recorded in `test-vectors.md`.

## Trust and remaining limits

FastNEAR discovery learns the derived public key; history services and selected RPCs learn queried account IDs, contracts and transaction hashes. Transaction submission sends signed bytes. No seed/private key is sent through those APIs and no borrowed API key is configured. Static inspection of the pinned SDK found no explicit direct-proxy override; actual Android/Tor traffic has not been captured.

The pinned kit still supplies indexed history and native account state. These services remain availability and history-integrity dependencies. The additional token read deliberately refuses the SDK's unverified token-balance fallback; it is not a general proof of node honesty or an audit of the SDK and protocols.

No funded send, pending/retry failure injection, device UI run or iOS parity run was completed by these reviews. No external iOS handoff was sent because that communication was not authorized. PAR-1, PAR-2 and PAR-3 remain unverified, recorded as follow-up work rather than passed checks.
